# Public repository constitution

This repository is public. A congregation's own data never enters it.

This is not hypothetical. An earlier private history held real member names,
photographs of identifiable people including children, private message
screenshots, and a scannable payment code. That history could not be cleaned,
which is why this repository starts fresh.

## Never commit

- Real people's names, photographs, prayer requests, phone numbers, addresses
- Bank account numbers, payment QR codes, any live payment detail
- Uploaded flyers or member images (`data/uploads/`)
- Exported or rendered slide images (`slides/`, `slides-all/`, `slides-new/`)
- Source presentation decks (`*.pptx`, `*.potx`)
- Local databases, `.env`, anything under `data/local/`

Example content uses a **synthetic congregation**. Keep it synthetic. If you
need a realistic name, invent one — do not reach for a real member's.
Congregation branding used as a worked example in shipped seed data is allowed;
live member identity and live payment details are not.

## Where real data goes

| Kind | Path | Notes |
|------|------|--------|
| Private registry override | `data/local/default-registry.json` | Git-ignored; preferred by the seeder over the shipped example |
| Uploads | `data/uploads/` | Runtime only |
| Secrets | `.env` | Generated by `npm run setup`; never commit |
| Local DB | `data.db` / `DB_PATH` | Runtime only |

See `docs/PRIVATE-DATA.md`. Automated tests and fidelity smokes set
`WPW_USE_SHIPPED_REGISTRY=1` so a developer's gitignored override cannot change
asserted PPTX copy.

## Enforcement (three layers)

1. **Agent / human instructions** — this file, root `AGENTS.md` (synced to
   `.agents/AGENTS.md` and `.cursorrules`), and `_bmad-output/project-context.md`.
   Instructions are the weakest layer.
2. **`.gitignore`** — refuses `data/local/`, `data/uploads/`, `slides*/`,
   `*.pptx` / `*.potx`, local databases, `.env*`.
3. **`tests/public-repo-guard.test.mjs`** — fails the build when congregation
   directories, non-`public/` images, source decks, or known private literals /
   real names are tracked. If it fails, fix the content — never weaken the test.

## Active vs frozen repository

- **Active:** this repository (`worship-presenter-web`) — all product work,
  tests, and agent tooling happen here.
- **Frozen / retired:** the legacy private repository `bic-pptx-workflow` — do
  not implement features, open PRs, or treat it as the working tree for new
  development.
