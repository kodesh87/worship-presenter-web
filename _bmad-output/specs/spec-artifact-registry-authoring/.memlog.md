- (direction) Correct Course: Artifact Registry must become the operator-facing ordered deck definition, not only an alphabetical template catalog.
- (direction) User accepts that past worship services need not be strongly preserved; optional registry clone/freeze is enough if historical fidelity is needed.
- (direction) Full canvas authoring vision is in scope: add/delete/reorder slides; change layout; insert/reposition/resize background, images, text, and text areas with font color/size/style including bold italic underline.
- (direction) Placeholders are a central predefined catalog; operators insert any predefined placeholder into any slide template and style it; adding a new placeholder kind still requires code.
- (direction) Presenter labels like Bible Talk Sequence must have an explicit edit boundary: operator can set base type display and the slide name/label in the registry.
- (decision) CAP-1: Ordered Artifact Registry is the SSOT for which slides exist and their sequence for live presentation generation.
- (decision) CAP-2: Administrators can create, delete, rename, and reorder slides in the ordered registry.
- (decision) CAP-3: Full canvas authoring on ordered slides — background, insert image/text/text-area, drag position, resize, font color/size/style (bold/italic/underline), Save required.
- (decision) CAP-4: Central predefined Placeholder Catalog; insert into any slide; style locally; new placeholder kinds are code-gated.
- (decision) CAP-5: Each slide has editable baseType (from the allowed set) and editable label; Presenter/list badges show [baseType] label.
- (decision) CAP-6: Optional Registry Clone/Freeze produces an immutable snapshot for historical services when an operator chooses to freeze.
- (decision) Weekly placeholder VALUES still come from worship-service intake (form/rundown/webhook); the ordered registry owns structure/layout/labels, not weekly hymn numbers or sermon titles.
- (constraint) buildSlidePlan (or its successor) must consume the ordered registry as the sequence source rather than a hard-coded Part A/B/C template list.
- (constraint) Adding a new predefined placeholder kind requires a code change; operators cannot invent arbitrary placeholder keys in the UI.
- (constraint) Public-repo rules unchanged: no congregation PII in git; private overrides stay in data/local/.
- (constraint) SongSet and Announcement expansion rules remain system-controlled children unless explicitly redesigned later.
- (non-goal) Per-service forked live editing of layouts during the service without Save.
- (assumption) Default shipped ordered registry mirrors today's buildSlidePlan sequence so existing Sabbath output is reproducible after migration.
- (assumption) Legacy services without a clone continue to render from stored parsed_data + then-current registry until an operator freezes a clone.
- (question) Should registry clone be automatic on first PPTX/present of a service date, or only on explicit Freeze action?
- (question) Do SongSet/Announcement remain non-canvas system expanders in v1 of this course, or must they become fully canvas-authored too?
