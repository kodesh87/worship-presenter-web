- (direction) Source: brainstorm-intent.md from brainstorm-worship-web-input-2026-07-19 session
- (direction) Intent: Web-based input channel for operators to create/edit worship service records independently of Telegram/PicoClaw webhook
- (capability) CAP-1: Operator can create a new worship service via structured web form at /services/new, producing ParsedRundown JSON stored in parsed_data
- (capability) CAP-2: Operator can edit an existing service using structured form fields alongside the existing raw-text mode on /services/[id]
- (capability) CAP-3: Hymn input supports dynamic-length list with autocomplete search by SDAH number or title from hymns table
- (capability) CAP-4: Date collision detection warns operator when a service already exists for the chosen date and offers to edit that service instead
- (capability) CAP-5: Form provides live preview using slide-plan rendering so operator sees projected output before saving
- (capability) CAP-6: Scripture fields (themeVerse, verseReading) accept reference strings with optional inline KJV text resolution
- (constraint) Web-created services write parsed_data directly (ParsedRundown shape); raw_payload is set to a marker string, not synthetic telegram text
- (constraint) Downstream consumers (slide-plan, PPTX, presenter) must remain untouched — web form produces identical ParsedRundown shape
- (constraint) Optimistic concurrency via updated_at (409 on stale write) must be honored in both create collision check and edit save
- (constraint) Auth: existing session cookie auth (operator+admin roles) — no new role needed
- (constraint) No new database tables — services table is sufficient; POST /api/services needs a new handler or extend webhook logic
- (decision) POST /api/services route handler to be created (currently only webhook creates services) — accepts structured JSON with source:web
- (decision) PUT /api/services/[id] already supports structured field patches via coerceStructuredFields — no backend change needed for edit
- (decision) Hymn search needs new API endpoint GET /api/hymns?q= to query hymns table for autocomplete
- (assumption) Assumed hymns table is fully populated (695 SDAH entries) and does not need import as part of this feature
- (assumption) Assumed existing EditForm raw textarea mode remains available as fallback — structured mode is additive
- (note) Non-goals: Telegram/PicoClaw changes, collaborative editing, draft staging table, mobile-specific UI, announcement management within worship form
